# 명세: 나를 기억하는 튜터 (v0.2, 2026-10-20)

상태: 조각 1~3 구현과 첫 학습자 카드 생성을 끝냈다(2026-10-20). 남은 것은 조각 4(정범의 실제 통화)와 조각 5(검증)다. 작업 순서는 10절에 있다.

## 1. 목표

정범 혼자 쓰는 새 영어 통화 앱(`~/dev/english-tutor`)에 고정 튜터 Ms. Park 한 명을 둔다. 튜터는 정범의 수준과 지난 통화를 기억한다. 매 통화를 그 기억에 맞춘다.

immergo(`~/dev/immergo`, 브랜치 english)는 그대로 둔다. 새 앱은 immergo의 통화 코드를 복사해서 시작한다(6절).

## 2. 그림

```
[통화 시작]
   │  서버가 학습자 카드 요약을 준다 (GET /api/learner-profile)
   ▼
[튜터 인사]  "지난번엔 과거형이 헷갈렸어요. 오늘은 ~"  (1~2문장)
   ▼
[상황극]     튜터가 미션 역할로 들어간다. 약점이 나올 상황을 만든다.
   ▼
[튜터 복귀]  역할을 끝내고 짧은 피드백 (30초 안, 쉬운 영어)
   ▼
[통화 종료] → 튜터링(tutoring/*.json, 한국어 요약) → 학습자 카드 갱신
                                                │
                       다음 통화 시작 때 다시 읽음 ◀┘
```

## 3. 사용자가 보는 흐름

1. 미션을 고르거나 "자유 대화"를 고른다.
2. 자유 대화는 오늘 주제를 쓰거나 자료(글·링크 본문)를 붙여 넣는다.
3. 통화가 연결되면 튜터가 먼저 말한다. 지난 약점 1개와 오늘 목표 1개를 말한다.
4. 튜터가 상황극으로 들어간다. 자유 대화는 상황극 없이 주제로 대화한다.
5. 끝나면 튜터가 자기 목소리로 돌아와 쉬운 영어로 짧게 피드백한다.
6. 통화를 끊으면 immergo와 같은 요약 화면이 한국어로 나온다. 뒤에서 카드가 갱신된다.

Teach-back 수업 모드는 코드를 그대로 가져오고 이번 범위에서 바꾸지 않는다.

## 4. 학습자 카드

위치: `~/dev/learning/english/learner-profile.json` (기존 `tutoring/` 옆).

```json
{
  "updated": "2026-10-20T09:00:00+09:00",
  "level": { "cefr": "B1.2", "actfl": "Intermediate High", "source": "level-test 2026-10-07" },
  "weak_points": [
    { "pattern": "과거형 (I just start → started)", "count": 2, "last_seen": "2026-10-16", "example": "I just started my day." }
  ],
  "fixed_points": [],
  "phrases": [ { "phrase": "based out of", "first_seen": "2026-10-16", "used_well": 0 } ],
  "pragmatics": [ { "pattern": "...", "note": "..." } ],
  "interests": [],
  "next_goal": "질문 시제·조동사"
}
```

- `weak_points`는 최대 5개를 둔다. 횟수와 최근성으로 순서를 정한다. 항목마다 선택 정수 `misses`(연속으로 안 나온 통화 수)가 있다.
- 약점이 최근 3회 통화에서 다시 나오지 않으면 `fixed_points`로 옮긴다.
- `level`은 레벨테스트로만 바뀐다. 통화로 자동 변경하지 않는다.
- 카드에는 이름·주소·회사 이름을 넣지 않는다. 카드는 매 통화마다 Google로 간다.

## 5. 동작

- 갱신: 튜터링(`run_tutoring`)이 성공하면 바로 뒤에 한 번 실행한다. 지금 카드와 새 튜터링 JSON을 모델에 주고 갱신된 카드 JSON을 받는다. immergo에서 가져온 `generate_text`(Vertex Gemini)를 쓴다.
- 검사: 받은 JSON이 4절 형식이 아니면 카드를 바꾸지 않는다. 로그를 남긴다.
- 백업: 바꾸기 전 카드를 `~/dev/learning/english/learner-profile-history/<시각>.json`에 복사한다.
- 주입: 통화 시작 때 서버가 카드를 짧은 영어 문단(1,200자 안)으로 바꿔 준다. `view-chat.js`가 미션·재통화·자유 대화 지시문 앞에 Ms. Park 인물 설정과 이 문단을 붙인다.
- 피드백 언어: 통화 안 피드백은 쉬운 영어(B1 수준 어휘, 짧은 문장)로 한다. 통화 뒤 요약 화면과 `tutoring/*.json`의 설명은 한국어로 한다.
- 긴 통화: 통화 서버는 컨텍스트 압축과 세션 재개를 켠다. 압축이 없으면 오디오 통화가 15분에서 끊기고, 연결 1회는 약 10분이다(`~/dev/learning/english/research/2026-10-20-realtime-tutor-stack.md` 2-2절).
- 첫 카드: 기존 튜터링 3개, 10-07 레벨테스트 결과, `learning-records/`로 한 번 만든다(스크립트 1회).

## 11. Pipecat 전환 (2026-10-20 사용자 결정)

통화 연결 부분만 Pipecat 1.13으로 바꾼다. 학습자 카드, 튜터링, Ms. Park 지시문, 전문 저장 형식, Teach-back은 그대로 둔다. 화면 개편은 12절에서 다룬다.

```
[브라우저] PipecatClient + SmallWebRTCTransport
   │  POST /api/offer (request_data: 지시문·모드·제한 시간)
   ▼
[서버] SmallWebRTCTransport.input → 원음 녹음(AudioBufferProcessor)
        → user aggregator → GeminiLiveVertexLLMService → transport.output → assistant aggregator
   │  턴 이벤트 → 전문 조각, complete_mission → 브라우저에 서버 메시지
   ▼
[통화 끝] sessions/*.md + 원음 WAV → 기존 /api/tutor → 학습자 카드
```

- 없어지는 것: `/api/auth`, `/ws`, `server/gemini_live.py`, `src/lib/gemini-live/*`, 브라우저 오디오 워크릿.
- 새로 생기는 것: `server/call_bot.py`(파이프라인), `POST/PATCH /api/offer`, `src/lib/call-client.js`(브라우저 연결).

| 결정 | 이유 | 틀리면 드는 비용 |
|---|---|---|
| 지시문은 지금처럼 브라우저가 만들어 `/api/offer`의 `request_data`로 보낸다 | `ms-park.js`와 미션·Teach-back 조립 코드를 재사용한다 | 서버로 옮길 때 한 번 이동 |
| 말 차례는 기본으로 Gemini 서버 VAD(10-16 조정값: 시작 민감, 1.2초 침묵)를 쓴다. `TURN_MODE=smart`이면 로컬 Silero VAD + Smart Turn v3.2로 판단한다 | 처음에는 검증된 설정으로 통화하고, Smart Turn은 비교 시험으로 켠다 | Smart Turn이 더 낫으면 기본값만 바꾼다 |
| 세션 재개·컨텍스트 압축은 Pipecat 내장 기능을 쓰고 자체 재연결 코드는 지운다 | 같은 기능을 두 번 갖지 않는다 | 없음 |
| 미션 완료(`complete_mission`)는 서버 함수가 받고 브라우저에 서버 메시지로 알린다 | 전문 머리의 `completed`를 서버가 바로 기록한다 | 없음 |
| 튜터가 먼저 말하는 신호는 서버가 연결 직후 넣는다(Teach-back 제외) | 브라우저 텍스트 경로가 없어진다 | 없음 |
| google-genai를 2.x로 올린다(Pipecat 요구) | 기존 시험 26개가 2.31에서 통과한다 | 없음 |
| 자동 통화 시험: aiortc로 만든 가짜 브라우저가 녹음 음성을 보내고 튜터 음성을 받는다 | 마이크 없이 통화 경로 전체를 확인한다 | 시험 1회에 Vertex 몇 센트 |
| 학습자가 이번 통화에서 3단어 이상 말하기 전의 `complete_mission`은 서버가 무시하고 "계속 대화하라"고 돌려준다 | 브라우저 시험에서 모델이 인사 직후 미션을 끝내고 학습자 카드 예문을 이번 발화처럼 인용했다. 자동 통화 시험에서도 다시 나타나 가드가 막았다 | 아주 짧게 말하고 끝내는 통화는 점수 없이 끝난다 |
| Teach-back에는 `complete_mission` 도구를 주지 않는다 | 수업 모드는 점수 없이 끝났다(f05f290과 같음) | 없음 |
| CORS 미들웨어를 두지 않고 `/api/offer`는 JSON 본문만 받는다(아니면 415) | 다른 웹 페이지가 내 Mac의 서버로 유료 통화를 열거나 수업 기록을 읽지 못하게 한다 | 다른 출처의 화면을 붙이려면 허용 출처를 명시해 다시 켠다 |
| 통화 시작 시각은 서버 시계 기준(`/api/status`의 Date 헤더로 차이 보정)으로 보낸다 | 폰 시계가 앞서면 튜터링이 이번 통화 전문을 못 찾는다 | 오차 1초 안쪽 |
| Ms. Park이 준비되기 전에 끊긴 연결은 요약으로 가지 않고 "다시 걸기"를 보여 준다 | 통화가 없었는데 빈 요약(15초 대기 뒤 404)을 보여 주지 않는다 | 없음 |

완료 조건: 단위 시험, 오프라인 검사 2개, `npm run build`, 자동 통화 시험 1회(튜터가 먼저 말함, `sessions/`에 미션 제목이 들어간 전문, 원음 WAV), 새 문맥 검증.

## 12. 화면 개편과 폰 접속 (2026-10-20 사용자 결정)

## 13. 통화 기록·Teach-back 기억·입 움직임·원어민 발음 (2026-10-20 사용자 결정)

사용자가 기능 4개를 모두 골랐다.

- **통화 기록·누적 숫자:** 홈의 "통화 기록" 줄에 누적(통화 수·분·날)을 보여 준다. 통화 기록 화면은 최신순 목록이고, 누르면 그 통화에 저장된 튜터링을 다시 본다(읽기 전용).
- **Teach-back에 기억:** "수업 중에" 도움 모드일 때 Ms. Park이 학습자 카드 요약을 참고해 끼어들 때를 정한다. 수업 튜터링 뒤에는 카드를 갱신한다.
- **입 움직임:** 통화 화면의 Ms. Park 얼굴은 목소리 크기에 맞춰 입이 열린다. 홈 얼굴은 그대로다.
- **원어민 발음:** 요약과 통화 기록의 고친 문장·잘한 표현·단어 옆 "발음 듣기"를 누르면, 원어민이 그 표현을 말하는 YouGlish 영상이 아래 시트로 뜬다.

### 에이전트가 정한 것

| 결정 | 이유 | 틀리면 드는 비용 |
|---|---|---|
| 통화 기록은 저장된 전문 머리글과 튜터링 JSON을 읽기만 한다(새 저장소 없음). stem은 `YYYY-MM-DD-HHMMSS`만 받는다(아니면 400) | 이미 있는 파일로 충분하다. 파일 경로를 바깥 값으로 만들지 않는다 | 기록이 수천 건이 되면 목록을 매번 다시 읽어 느려진다. 그때 색인을 둔다 |
| Teach-back 카드 갱신에서 `unanswered`를 뺀다 | 답하지 못한 질문은 보안 지식의 빈칸이지 영어 약점이 아니다 | 카드에 수업 이해도가 남지 않는다 |
| "수업 끝나고" 모드에는 기억 문단을 넣지 않는다 | 그 모드의 Ms. Park은 수업 중에 말하지 않는다 | 없음 |
| 입은 그림 위에 SVG를 겹쳐 그리고, 움직임 줄이기 설정이면 그리지 않는다 | 그림 1장으로 끝난다. 얼굴 그림을 바꾸면 입 위치(`TalkingPortrait.tsx`)도 다시 잰다 | 그림을 바꿀 때 입 위치를 다시 잰다 |
| YouGlish는 공식 `widget.js`를 쓰지 않고 임베드 페이지(`/pronounce/<표현>/english/us/emb=1`)를 sandbox iframe으로 띄운다. 항상 "YouGlish에서 열기" 링크를 둔다 | `widget.js`는 앱과 같은 출처에서 돌아 유료 통화(`/api/offer`)와 통화 기록 API에 닿을 수 있다. iframe은 YouGlish 출처에만 머문다. 결과가 없으면 YouGlish가 직접 "No result found"를 보여 준다 | 임베드 주소는 문서화되지 않았다. 바뀌면 링크만 남는다. 누른 표현만 YouGlish로 간다 |

## 14. readgloss 단어 기능과 잇기 (2026-10-20 사용자 결정 "양쪽 다")

readgloss(`~/dev/readgloss`, 영어 읽기 확장)의 단어 기능과만 잇는다. 메모·스크랩·개념·공부 시간은 잇지 않는다.

- **readgloss → 통화:** 홈의 "읽다가 찾아본 단어" 카드에 단어를 최대 5개 보여 준다. 순서는 오늘 복습할 단어장 단어, 최근 14일에 찾아본 단어, 단어장 최근 단어이고 아는 단어는 뺀다. 미션·자유 대화 지시문에 같은 단어를 넣어 Ms. Park이 2~3개를 자연스럽게 쓰게 한다. Teach-back에는 넣지 않는다(수업 내용에 집중).
- **요약:** 그 단어 중 이번 통화에서 내가 실제로 쓴 단어(원형과 흔한 굴절형 -s·-ed·-ing 등)를 표시한다.
- **통화 → readgloss:** 튜터링의 새 단어(한 낱말은 단어장, 여러 낱말은 구 항목)와 고친 표현(구 항목, 종류 expression)을 통화당 한 번 readgloss에 넣는다. Teach-back 튜터링도 같다. 넣은 항목은 readgloss 복습 고리(상자 1, 오늘)에 들어간다. 요약에 넣은 개수를 보여 준다.

### 에이전트가 정한 것

| 결정 | 이유 | 틀리면 드는 비용 |
|---|---|---|
| readgloss 다리 API(`GET /words`·`GET /words/review`·`POST /words`, 토큰 `~/dev/readgloss/data/token`)만 쓰고 readgloss 데이터 파일은 직접 읽지 않는다. 바꿀 때는 `READGLOSS_URL`·`READGLOSS_TOKEN_FILE` | 다리가 저장 형식과 복습 상태를 책임진다. readgloss 코드는 바꾸지 않는다 | 다리 API가 바뀌면 `server/readgloss.py`만 고친다 |
| 다리가 꺼져 있거나 토큰이 틀리면 조용히 건너뛴다(홈 카드 없음, 요약에 넣은 개수 없음). 넣기가 실패한 통화는 다음 튜터링 요청 때 다시 시도한다 | 통화 앱은 readgloss 없이도 돌아야 한다 | 다리가 꺼진 날의 단어는 그날 다시 요약을 열지 않으면 빠진다 |
| Google로 가는 지시문에는 원형과 한국어 뜻(40자)만 넣고 읽던 문장·페이지 주소는 넣지 않는다. readgloss에 넣을 때도 통화 문장·주소는 비운다 | 읽던 페이지 내용이 Google로 가지 않게 한다 | 단어 쓰임 예문이 없어 Ms. Park이 뜻을 조금 덜 정확히 쓸 수 있다 |
| 다리 요청은 Host 머리글을 `127.0.0.1:47831`로 보낸다 | 다리가 DNS 리바인딩을 막으려고 Host를 고정 검사한다. 시험 다리를 다른 포트에 띄워도 같은 값을 받는다 | 없음 |
| 같은 단어·같은 표현을 다시 넣어도 readgloss가 항목 하나로 두고 복습 상태를 유지한다(다리 규칙). 통화 앱은 같은 통화를 서버가 켜져 있는 동안 한 번만 넣는다 | 중복 항목이 생기지 않는다 | 서버를 껐다 켜고 같은 통화를 다시 정리하면 저장 시각만 새로 바뀐다 |
| 레벨은 readgloss에 보내지 않는다 | readgloss는 단어마다 "모를 확률"을 내 기록으로 이미 맞춘다(readgloss 명세 변경 기록 20). 주석 수준 설정은 확장 설정이라 다리에 없다 | readgloss 수준(기본 C1)을 내 레벨(B1.2)에 맞추려면 확장 패널에서 직접 B1을 고른다 |
